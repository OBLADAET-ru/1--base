§1. Основы платформы 1С:Предприятие

Архитектура, режимы работы и ключевые понятия

1.1

Что такое 1С:Предприятие

1С:Предприятие 8 — это технологическая платформа для создания прикладных решений (конфигураций) в области автоматизации бизнеса. Платформа предоставляет разработчику объектную модель, встроенный язык программирования и среду исполнения.

Прикладное решение (конфигурация) — это совокупность объектов метаданных, код на встроенном языке и интерфейс, которые описывают конкретную предметную область (бухгалтерия, торговля, склад и т.д.).

ℹ️ Важно: Разработчик работает с метаданными, а платформа автоматически генерирует физические структуры базы данных. Вы не создаёте таблицы вручную — вы описываете объекты, а платформа делает всё остальное.
1.2

Режимы работы

Платформа имеет два основных режима работы:

РежимНазначениеДля кого
КонфигураторСреда разработки: создание объектов, написание кода, отладка, реструктуризация БДРазработчик
ПредприятиеПользовательский режим: ввод документов, формирование отчётовКонечный пользователь
1.3

Ключевые объекты конфигурации

Основные объекты метаданных, с которыми работает разработчик:

ОбъектНазначениеПример
СправочникУсловно-постоянная информацияНоменклатура, Контрагенты, Сотрудники
ДокументРегистрация фактов деятельностиРеализацияТоваров, ПоступлениеТоваров
Регистр сведенийДанные в разрезе измеренийЦеныНоменклатуры, КурсыВалют
Регистр накопленияУчёт движений (остатки, обороты)ТоварыНаСкладах, Взаиморасчёты
ОтчётАналитическая информацияОстаткиТоваров, ПродажиЗаПериод
ОбработкаСервисные операцииЗагрузкаДанных, ГрупповаяОбработка
Общий модульБиблиотека процедур и функцийОбщегоНазначения, РаботаСФайлами
1.4

Программные модули

Код на встроенном языке размещается в программных модулях. Контекст выполнения модуля определяет доступные свойства и методы.

  • Глобальный контекст — доступен из любого модуля: общие функции платформы (Сообщить, ТекущаяДата, Новый).
  • Локальный контекст — свойства и методы конкретного объекта (реквизиты формы, модуль документа).

Виды модулей:

  • Модуль приложения
  • Модуль сеанса
  • Общие модули (глобальные и неглобальные)
  • Модули объектов (справочников, документов)
  • Модули менеджеров
  • Модули форм
  • Модули команд
💡 Совет: Размещайте общие процедуры и функции в общих модулях. Это улучшает читаемость кода и позволяет переиспользовать логику в разных объектах.

§2. Синтаксис встроенного языка

Базовые конструкции языка 1С

2.1

Переменные и операторы

Переменные в 1С имеют мягкую типизацию: тип определяется значением, которое присвоено переменной. Объявление переменной необязательно, но рекомендуется для ясности кода.

// Объявление переменных
Перем ИмяПеременной;
Перем Счетчик, Сумма, Результат;

// Присваивание значений
Сумма = 100;
Строка = "Привет, 1С!";
МодульЧисла = -5; // Унарный минус
2.2

Арифметические операции

ОперацияСинтаксисПример
Сложениеa + b5 + 3 = 8
Вычитаниеa - b5 - 3 = 2
Умножениеa * b5 * 3 = 15
Делениеa / b10 / 2 = 5
Остаток от деленияa % b10 % 3 = 1
2.3

Логические операции

Логические операции применяются к значениям типа Булево (Истина/Ложь):

ОперацияСинтаксисОписание
ОтрицаниеНЕИнверсия значения
КонъюнкцияИЛогическое И
ДизъюнкцияИЛИЛогическое ИЛИ
2.4

Условные операторы

Если Сумма > 1000 Тогда
    Сообщить("Большая сумма");
ИначеЕсли Сумма > 100 Тогда
    Сообщить("Средняя сумма");
Иначе
    Сообщить("Малая сумма");
КонецЕсли;
2.5

Циклы

Цикл Для

Для Сч = 1 По 10 Цикл
    Сообщить(Сч);
КонецЦикла;

Цикл Для Каждого

Для Каждого Элемент Из Массив Цикл
    Сообщить(Элемент);
КонецЦикла;

Цикл Пока

Счетчик = 0;
Пока Счетчик < 10 Цикл
    Счетчик = Счетчик + 1;
КонецЦикла;
⚠️ Важно: В 1С нет оператора break или continue. Для досрочного выхода из цикла используется условие в заголовке или флаг.

Главная / §4 Коллекции

§4. Коллекции значений

Массивы, структуры, соответствия и таблицы

4.1

Массив

Упорядоченный набор значений. Ключом всегда является индекс (число).

Массив = Новый Массив;
Массив.Добавить(10);
Массив.Добавить("текст");
Массив.Добавить(Истина); // Разные типы — норма

Размер = Массив.Количество();

Для Каждого Элемент Из Массив Цикл
    Сообщить(Элемент);
КонецЦикла;
4.2

Структура

Набор значений с доступом по имени (ключу). Ключом может быть любой тип.

Структура = Новый Структура;
Структура.Вставить("Имя", "Иван");
Структура.Вставить("Возраст", 30);

Сообщить(Структура.Имя);
Сообщить(Структура["Возраст"]);

Если Структура.Свойство("Имя") Тогда
    // ...
КонецЕсли;
4.3

Соответствие

Похоже на структуру, но ключом может быть строка с пробелами и любой другой тип.

Соответствие = Новый Соответствие;
Соответствие.Вставить("Ключ1", 100);
Соответствие.Вставить("Ключ2", 200);

Значение = Соответствие["Ключ1"]; // 100
4.4

Таблица значений

Двумерная таблица с колонками и строками. Колонки имеют имена и типы.

ТЗ = Новый ТаблицаЗначений;
ТЗ.Колонки.Добавить("Наименование");
ТЗ.Колонки.Добавить("Количество", Новый ОписаниеТипов("Число"));

Строка = ТЗ.Добавить();
Строка.Наименование = "Товар 1";
Строка.Количество = 5;

// Сортировка
ТЗ.Сортировать("Количество УБЫВ");

// Свернуть (аналог GROUP BY)
ТЗ.Свернуть("Наименование", "Количество");
💡 Совет: Для возврата нескольких значений из функции часто используют Структуру. Для табличных данных — ТаблицуЗначений.

§5. Процедуры и функции

Структура и особенности

5.1

Процедуры

Процедура — именованный блок кода, который выполняет действие, но не возвращает значение.

Процедура Приветствие(Имя)
    Сообщить("Привет, " + Имя);
КонецПроцедуры

// Вызов
Приветствие("Мир");
5.2

Функции

Функция — блок кода, который возвращает значение через оператор Возврат.

Функция Сложить(А, Б)
    Возврат А + Б;
КонецФункции

Результат = Сложить(5, 3); // 8
5.3

Экспортные процедуры и функции

Ключевое слово Экспорт делает процедуру или функцию доступной из других модулей.

Функция ПолучитьКурсВалюты(Валюта, Дата) Экспорт
    // Логика получения курса
    Возврат Курс;
КонецФункции
5.4

Параметры по умолчанию

Функция РассчитатьСкидку(Сумма, Процент = 5)
    Возврат Сумма * Процент / 100;
КонецФункции

Скидка = РассчитатьСкидку(1000);      // 50 (5%)
Скидка = РассчитатьСкидку(1000, 10); // 100 (10%)

§6. Язык запросов 1С

Основной инструмент получения данных

6.1

Что такое запрос

Запросы в 1С работают не с физическими таблицами СУБД, а с таблицами запросов — «образами», которые предоставляет платформа. Это позволяет использовать понятные имена объектов конфигурации.

ℹ️ Важно: Язык запросов 1С не является чистым SQL. Он транслируется в диалект конкретной СУБД (MS SQL, PostgreSQL, Oracle, IBM DB2).
6.2

Структура запроса

Запрос = Новый Запрос;
Запрос.Текст =
"ВЫБРАТЬ
|    Номенклатура.Ссылка КАК Ссылка,
|    Номенклатура.Наименование КАК Наименование
|ИЗ
|    Справочник.Номенклатура КАК Номенклатура
|ГДЕ
|    Номенклатура.Цена > &МинЦена
|УПОРЯДОЧИТЬ ПО
|    Наименование";

Запрос.УстановитьПараметр("МинЦена", 1000);
6.3

Соединения таблиц

ВЫБРАТЬ
    Док.Ссылка КАК Документ,
    Товар.Номенклатура.Наименование КАК Товар
ИЗ
    Документ.РеализацияТоваров КАК Док
    ВНУТРЕННЕЕ СОЕДИНЕНИЕ Документ.РеализацияТоваров.Товары КАК Товар
    ПО Док.Ссылка = Товар.Ссылка
6.4

Группировка

ВЫБРАТЬ
    Товары.Номенклатура КАК Номенклатура,
    СУММА(Товары.Количество) КАК ВсегоКоличество

ИМЕЮЩИЕ
    СУММА(Товары.Сумма) > 100000

Временные таблицы

Запрос.Текст =
"ВЫБРАТЬ
|    Номенклатура.Ссылка КАК Номенклатура
|ПОМЕСТИТЬ ВТ_Товары
|ИЗ
|    Справочник.Номенклатура КАК Номенклатура

§7. SQL и взаимодействие с СУБД

Особенности работы с базами данных

7.1

Отличия от чистого SQL

  • Обращение к объектам метаданных, а не к таблицам напрямую
  • Точки в ссылочных полях: Документ.Контрагент.Наименование
  • Автоматическое соединение при обращении через точку
  • Ключевые слова на русском языке
7.2

Таблицы запросов

Вы не можете обратиться к таблице СУБД напрямую. Вы обращаетесь к «образу» таблицы, который предоставляет платформа.

🚫 Не рекомендуется: Прямая работа с таблицами СУБД в обход платформы нарушает целостность данных и не поддерживается.

Главная / §9 Управляемые формы

§9. Управляемые формы

Архитектура и конструирование интерфейса

9.1

Что такое управляемая форма

Управляемая форма — это объект, который создаётся на сервере согласно настройкам в конфигураторе, а затем выводится в клиентском приложении [citation:2][citation:5].

Благодаря этой архитектуре, форма существует одновременно и на сервере, и на клиенте. У неё есть серверный и клиентский контекст выполнения кода [citation:5][citation:9].

ℹ️ Ключевая идея: На стороне клиента форма только прорисовывается. Все операции с данными, вычисления и доступ к информационной базе выполняются на сервере [citation:2][citation:5].
9.2

Конструктор формы — 7 закладок

В конфигураторе форма редактируется через конструктор, который содержит 7 закладок [citation:2]:

ЗакладкаНазначение
ЭлементыСостав и порядок элементов управления на форме
Командный интерфейсВидимость и расположение команд
РеквизитыДанные, с которыми работает форма
КомандыКоманды формы: собственные, стандартные, глобальные
ПараметрыДанные для настройки формы при открытии
ФормаПредварительный просмотр формы
МодульАлгоритмы взаимодействия на встроенном языке
9.3

Директивы компиляции

Разработчик сам указывает, какой код выполняется на сервере, а какой на клиенте, при помощи директив [citation:2][citation:5]:

ДирективаКонтекст выполнения
&НаКлиентеВыполняется на машине пользователя
&НаСервереВыполняется на сервере, с доступом ко всем данным формы
&НаСервереБезКонтекстаВыполняется на сервере, без передачи данных формы
&НаКлиентеНаСервереКомбинированный вызов
&НаКлиентеНаСервереБезКонтекстаКомбинированный вызов без контекста
💡 Рекомендация: Используйте НаСервереБезКонтекста, когда данные формы не нужны на сервере — это быстрее, так как не тратится время на сериализацию данных.
9.4

Виды элементов формы

В форме используются пять основных видов элементов :

ЭлементНазначение
ПолеОтображение и ввод данных (текстовые, числовые, ссылочные)
ГруппаГруппировка элементов: Обычная группа, Страницы, Командная панель, Подменю
КнопкаВыполнение команд, гиперссылки
ТаблицаОтображение и редактирование табличных данных
ДекорацияНадпись, Картинка
9.5

Основной реквизит формы

Если у формы есть основной реквизит, это определяет её функциональность. Например, если основной реквизит — документ, то при закрытии формы система запросит подтверждение записи .

От типа основного реквизита зависит набор доступных свойств и методов в модуле формы .

§10. События и обработчики форм

Реакция на действия пользователя

10.1

Что такое событие

Событие — это момент в работе формы или её элементов, когда система может передать управление коду разработчика. Используя встроенный язык, разработчик может «вклиниться» в эти события и описать собственный алгоритм [citation:12][citation:16].

10.2

Основные события формы

СобытиеКогда возникает
ПриСозданииНаСервереПри создании формы
ПриОткрытииПеред открытием формы
ПриЧтенииНаСервереПосле чтения объекта с сервера
ПередЗаписьюПеред записью объекта в базу
ПослеЗаписиПосле записи объекта
ПриЗакрытииПри завершении работы с формой
10.3

События элементов формы

СобытиеНазначение
ПриИзмененииВозникает после изменения значения поля

ОбработкаВыбораПосле выбора значения
ПриАктивизацииСтрокиПри переходе к другой строке таблицы
10.4

Пример: автопересчёт суммы

Классический пример обработки события ПриИзменении для поля табличной части — автоматический пересчёт суммы при изменении количества [citation:16][citation:19]:

&НаКлиенте
Процедура МатериалыКоличествоПриИзменении(Элемент)
    СтрокаТабличнойЧасти = Элементы.Материалы.ТекущиеДанные;
    СтрокаТабличнойЧасти.Сумма =
        СтрокаТабличнойЧасти.Количество * СтрокаТабличнойЧасти.Цена;
КонецПроцедуры
ℹ️ Разбор: Элементы.Материалы — обращение к табличной части на форме. ТекущиеДанные — строка, с которой работает пользователь [citation:16].
10.5

Вынос логики в общий модуль

Если одинаковый расчёт нужен в нескольких документах, логику выносят в общий модуль [citation:19]:

// Общий модуль РаботаСДокументами
Процедура РассчитатьСумму(СтрокаТабличнойЧасти) Экспорт
    СтрокаТабличнойЧасти.Сумма =
        СтрокаТабличнойЧасти.Количество * СтрокаТабличнойЧасти.Цена;
КонецПроцедуры

// В модуле формы документа
&НаКлиенте
Процедура МатериалыКоличествоПриИзменении(Элемент)
    РаботаСДокументами.РассчитатьСумму(
        Элементы.Материалы.ТекущиеДанные);
КонецПроцедуры

§11. Отчёты и система компоновки данных

Гибкая настройка отчётности

11.1

Что такое СКД

Система компоновки данных (СКД) — механизм платформы, позволяющий создавать отчёты на основе декларативного описания: наборы данных, связи, вычисляемые поля, ресурсы, параметры и настройки.

11.2

Составные части схемы

ЧастьНазначение
Наборы данныхЗапросы и объекты
Связи наборовСоединение нескольких наборов
Вычисляемые поляПоля по формулам
РесурсыАгрегируемые поля (Сумма, Количество)
ПараметрыВходные значения для отбора
НастройкиГруппировки, отборы, оформление
11.3

Программное выполнение СКД

Схема = ПолучитьМакет("СхемаКомпоновкиДанных");
Настройки = Схема.НастройкиПоУмолчанию;

    "НачалоПериода", НачалоМесяца(ТекущаяДата()));

Компоновщик = Новый КомпоновщикМакетаКомпоновкиДанных;
Макет = Компоновщик.Выполнить(Схема, Настройки);

Главная / §14 Оптимизация

§14. Оптимизация производительности

Быстрые запросы и эффективный код

14.1

Правила оптимизации запросов

  1. Не используйте * — перечисляйте поля явно
  2. Избегайте соединений с подзапросами — используйте временные таблицы
  3. Ставьте условия в ГДЕ, а не в ИМЕЮЩИЕ где возможно
  4. Индексируйте поля для отбора и соединения
  5. Не используйте В (&Массив) с >1000 элементов
  6. Используйте ПЕРВЫЕ N для ограничения выборки
14.2

Пакетная обработка данных

// Плохо: чтение всех записей
Выборка = Регистр.Выбрать();
Пока Выборка.Следующий() Цикл ... КонецЦикла;

// Хорошо: пакетная обработка
Выборка = Регистр.Выбрать(Порядок, Порция);
Пока Выборка.Следующий() Цикл
    ОбработатьПорцию(Выборка.Выгрузить());
КонецЦикла;

  • Технологический журнал — события CALL, DBMSSQL, EXCP
  • Apdex — индекс производительности
